# AI 协作开发流程规范

## 1. 概述

本文档规定了基于 AI 协作的软件开发生命周期（SDLC）流程，确保每个新功能都经过严格的设计、评审、开发、测试和回归流程，所有环节都有留档和打分机制。

## 3. 角色定义

### 3.1 产品经理 (PM)
- **职责**: 需求分析、PRD 编写、需求评审组织
- **输出**: 
  - 需求文档 (PRD)
  - 用户故事 (User Stories)
  - 验收标准 (Acceptance Criteria)
- **打分标准**: 需求完整性、可行性、用户价值

### 3.2 架构师 (Architect)
- **职责**: 系统架构设计、技术选型、架构评审
- **输出**:
  - 架构设计文档 (ADD)
  - 技术选型报告
  - 风险评估报告
- **打分标准**: 架构合理性、扩展性、性能、安全性

### 3.3 设计师 (Designer)
- **职责**: 详细设计、接口设计、数据库设计
- **输出**:
  - 详细设计文档 (DDD)
  - API 接口文档
  - 数据库设计文档
- **打分标准**: 设计完整性、规范性、可维护性

### 3.4 开发者 (Developer)
- **职责**: 代码实现、单元测试、代码审查
- **输出**:
  - 源代码
  - 单元测试
  - 开发文档
- **打分标准**: 代码质量、测试覆盖率、文档完整性

### 3.5 测试工程师 (QA)
- **职责**: 测试用例设计、功能测试、性能测试
- **输出**:
  - 测试用例
  - 测试报告
  - Bug 清单
- **打分标准**: 测试覆盖率、Bug 发现率、测试报告质量

### 3.6 回归测试员 (Regression QA)
- **职责**: 回归测试、兼容性测试、稳定性测试
- **输出**:
  - 回归测试报告
  - 兼容性测试报告
- **打分标准**: 回归覆盖率、问题发现率

### 3.7 运维工程师 (DevOps)
- **职责**: 部署、监控、运维
- **输出**:
  - 部署脚本
  - 监控配置
  - 运维文档
- **打分标准**: 部署成功率、监控覆盖率、文档完整性

## 4. 评审流程

### 4.1 评审类型

| 评审类型 | 时机 | 参与角色 | 通过分数 |
|:---|:---|:---|:---:|
| 需求评审 | Phase 1 完成后 | PM、架构师、开发、测试 | ≥ 80 |
| 架构评审 | Phase 2 完成后 | 架构师、开发、测试 | ≥ 85 |
| 设计评审 | Phase 3 完成后 | 开发、测试 | ≥ 80 |
| 代码审查 | Phase 4 完成后 | 开发（至少 1 人） | 通过/不通过 |
| 测试评审 | Phase 5 完成后 | 测试、开发 | ≥ 90 |
| 发布评审 | Phase 7 前 | 全角色 | 全部通过 |

### 4.2 评审打分标准

#### 需求评审打分项
- 需求完整性 (20分): 是否覆盖所有用户场景
- 需求清晰度 (20分): 描述是否清晰、无歧义
- 可行性 (20分): 技术、时间、资源是否可行
- 用户价值 (20分): 是否解决用户痛点
- 验收标准 (20分): 是否明确、可测量

#### 架构评审打分项
- 架构合理性 (25分): 是否符合业务需求
- 扩展性 (20分): 是否易于扩展
- 性能 (20分): 是否满足性能要求
- 安全性 (20分): 是否有安全风险
- 技术选型 (15分): 技术选型是否合理

#### 设计评审打分项
- 设计完整性 (25分): 是否覆盖所有功能模块
- 接口规范性 (25分): API 设计是否规范
- 数据库设计 (25分): 表结构是否合理
- 可维护性 (25分): 是否易于维护和扩展

### 4.3 评审流程

```
1. 评审发起人提交评审申请
   ↓
2. 评审材料提前 24 小时分发
   ↓
3. 评审会议（或异步评审）
   ↓
4. 评审打分
   ↓
5. 记录评审意见
   ↓
6. 打分 ≥ 通过分数 → 进入下一阶段
   打分 < 通过分数 → 修改后重新评审
   ↓
7. 评审记录归档
```

## 7. 违规处理

### 7.1 流程违规
- 跳过评审环节 → 回退到上一阶段
- 评审未通过就开发 → 暂停开发，重新评审
- 测试未通过就发布 → 禁止发布

### 7.2 质量违规
- 代码质量差 → 重新开发
- Bug 率高 → 加强测试
- 文档缺失 → 补充文档

## 8. 持续改进

### 8.1 复盘机制
- 每个项目结束后进行复盘
- 收集各角色反馈
- 优化流程和工具

### 8.2 度量指标
- 需求变更率
- 缺陷密度
- 测试覆盖率
- 交付周期
- 客户满意度
