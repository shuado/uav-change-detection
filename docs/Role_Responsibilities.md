# 角色职责详细说明

## 1. 产品经理 (Product Manager)

### 核心职责
- 需求收集与分析
- 产品规划与路线图
- 需求文档 (PRD) 编写
- 需求评审组织
- 项目进度跟踪
- 用户沟通与反馈

### 输入
- 用户反馈
- 市场调研
- 竞品分析
- 业务目标

### 输出
- 需求文档 (PRD)
- 用户故事 (User Stories)
- 产品路线图
- 验收标准 (Acceptance Criteria)
- 需求评审记录

### 技能要求
- 业务理解能力
- 沟通协调能力
- 文档编写能力
- 项目管理能力

### 工作流程
```
1. 收集需求（用户反馈、市场调研）
   ↓
2. 分析需求（可行性、优先级、价值）
   ↓
3. 编写 PRD（功能描述、用户故事、验收标准）
   ↓
4. 组织需求评审
   ↓
5. 收集评审意见，修改完善
   ↓
6. 评审通过，进入设计阶段
   ↓
7. 跟踪开发进度
   ↓
8. 验收产品
```

### 质量标准
- PRD 完整性 ≥ 90%
- 用户故事清晰度 ≥ 85%
- 需求变更率 ≤ 10%
- 用户满意度 ≥ 80%

## 2. 架构师 (Architect)

### 核心职责
- 系统架构设计
- 技术选型
- 架构评审
- 技术风险评估
- 技术难题攻关
- 技术规范制定

### 输入
- 需求文档 (PRD)
- 性能要求
- 安全要求
- 技术约束

### 输出
- 架构设计文档 (ADD)
- 技术选型报告
- 风险评估报告
- 架构评审记录
- 技术规范文档

### 技能要求
- 系统设计能力
- 技术广度与深度
- 抽象思维能力
- 风险评估能力

### 工作流程
```
1. 阅读 PRD，理解需求
   ↓
2. 分析技术约束和性能要求
   ↓
3. 设计系统架构（分层、模块、接口）
   ↓
4. 技术选型（框架、数据库、中间件）
   ↓
5. 风险评估（技术、性能、安全）
   ↓
6. 编写架构设计文档
   ↓
7. 组织架构评审
   ↓
8. 收集评审意见，修改完善
   ↓
9. 评审通过，进入详细设计
   ↓
10. 指导开发，解决技术难题
```

### 质量标准
- 架构合理性 ≥ 90%
- 技术选型合理性 ≥ 85%
- 性能达标率 ≥ 95%
- 安全事故率 = 0

---

## 3. 设计师 (Designer)

### 核心职责
- 详细设计
- 接口设计 (API)
- 数据库设计
- 设计评审
- 设计文档维护

### 输入
- 架构设计文档 (ADD)
- 需求文档 (PRD)
- 技术规范

### 输出
- 详细设计文档 (DDD)
- API 接口文档
- 数据库设计文档
- 设计评审记录
- 数据字典

### 技能要求
- 详细设计能力
- 接口设计能力
- 数据库设计能力
- 文档编写能力

### 工作流程
```
1. 阅读架构设计文档
   ↓
2. 细化模块设计（类、方法、属性）
   ↓
3. 设计 API 接口（URL、参数、返回值）
   ↓
4. 设计数据库表结构（字段、索引、关系）
   ↓
5. 编写详细设计文档
   ↓
6. 组织设计评审
   ↓
7. 收集评审意见，修改完善
   ↓
8. 评审通过，进入开发阶段
   ↓
9. 支持开发，解答设计问题
```

### 质量标准
- 设计完整性 ≥ 95%
- 接口规范性 ≥ 90%
- 数据库设计合理性 ≥ 90%
- 设计变更率 ≤ 5%

---

## 4. 开发者 (Developer)

### 核心职责
- 代码实现
- 单元测试编写
- 代码审查
- 开发文档编写
- Bug 修复

### 输入
- 详细设计文档 (DDD)
- API 接口文档
- 数据库设计文档
- 开发规范

### 输出
- 源代码
- 单元测试
- 开发文档
- 代码审查记录
- Bug 修复记录

### 技能要求
- 编程能力
- 调试能力
- 测试能力
- 文档编写能力

### 工作流程
```
1. 阅读详细设计文档
   ↓
2. 创建功能分支
   ↓
3. 编写代码（遵循开发规范）
   ↓
4. 编写单元测试（覆盖率 ≥ 80%）
   ↓
5. 自测（功能、性能、安全）
   ↓
6. 提交代码审查 (PR)
   ↓
7. 根据审查意见修改代码
   ↓
8. 审查通过，合并代码
   ↓
9. 编写开发文档
   ↓
10. 支持测试，修复 Bug
```

### 质量标准
- 代码质量评分 ≥ 85
- 单元测试覆盖率 ≥ 80%
- 代码审查通过率 ≥ 90%
- Bug 修复及时率 ≥ 95%

---

## 5. 测试工程师 (QA Engineer)

### 核心职责
- 测试用例设计
- 功能测试执行
- 性能测试
- 安全测试
- 测试报告编写
- Bug 跟踪

### 输入
- 需求文档 (PRD)
- 设计文档
- 测试规范

### 输出
- 测试用例
- 测试报告
- Bug 清单
- 测试评审记录
- 性能测试报告

### 技能要求
- 测试设计能力
- 测试执行能力
- 自动化测试能力
- 问题定位能力

### 工作流程
```
1. 阅读需求和设计文档
   ↓
2. 设计测试用例（功能、边界、异常）
   ↓
3. 准备测试数据和环境
   ↓
4. 执行测试（手动 + 自动化）
   ↓
5. 记录 Bug（严重程度、优先级）
   ↓
6. 跟踪 Bug 修复
   ↓
7. 回归测试
   ↓
8. 编写测试报告
   ↓
9. 组织测试评审
   ↓
10. 评审通过，进入回归测试
```

### 质量标准
- 测试用例覆盖率 ≥ 95%
- 测试用例通过率 ≥ 95%
- Bug 发现率 ≥ 90%
- 漏测率 ≤ 5%

---

## 6. 回归测试员 (Regression QA)

### 核心职责
- 回归测试执行
- 兼容性测试
- 稳定性测试
- 回归测试报告编写

### 输入
- 测试用例
- 变更清单
- 历史 Bug 清单

### 输出
- 回归测试报告
- 兼容性测试报告
- 稳定性测试报告
- 回归测试记录

### 技能要求
- 回归测试能力
- 兼容性测试能力
- 问题定位能力

### 工作流程
```
1. 分析变更清单
   ↓
2. 确定回归测试范围
   ↓
3. 选择回归测试用例
   ↓
4. 执行回归测试
   ↓
5. 执行兼容性测试（多浏览器、多设备）
   ↓
6. 执行稳定性测试（长时间运行）
   ↓
7. 记录问题
   ↓
8. 编写回归测试报告
   ↓
9. 确认回归测试通过
```

### 质量标准
- 回归测试覆盖率 = 100%
- 回归测试通过率 = 100%
- 兼容性问题率 ≤ 2%
- 稳定性问题率 = 0

---

## 7. 运维工程师 (DevOps Engineer)

### 核心职责
- 环境部署
- 持续集成/持续部署 (CI/CD)
- 监控配置
- 日志管理
- 性能优化
- 故障处理

### 输入
- 发布清单
- 部署文档
- 监控需求

### 输出
- 部署脚本
- CI/CD 配置
- 监控配置
- 运维文档
- 故障处理记录

### 技能要求
- 部署能力
- 自动化能力
- 监控能力
- 故障处理能力

### 工作流程
```
1. 阅读发布清单和部署文档
   ↓
2. 准备部署环境
   ↓
3. 编写部署脚本
   ↓
4. 配置 CI/CD 流水线
   ↓
5. 执行部署
   ↓
6. 配置监控和告警
   ↓
7. 验证部署成功
   ↓
8. 编写运维文档
   ↓
9. 组织发布评审
   ↓
10. 监控运行状态
   ↓
11. 处理故障
```

### 质量标准
- 部署成功率 ≥ 99%
- 系统可用性 ≥ 99.9%
- 故障响应时间 ≤ 5 分钟
- 故障恢复时间 ≤ 30 分钟
